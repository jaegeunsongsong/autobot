# 검토: 무인 아기 사진 스튜디오 IoT·무인 운영 설비 (설계서 261014)

검토일 2026-10-14. 설치일 10/16 전 "빠진 것·위험한 것·과한 것" 중심. 확인 못 한 제품 기능은 **(추정)** 또는 **(확인 필요)** 로 표시. 근거는 `docs/aqara-iot/` 노트와 당일 추가 확인(아카라라이프 K100 FAQ, 아카라 포럼 자동화 2.0 강좌, T2 전구·H2·E1 사양).

A1 펄스는 매 입장마다 전구 14개를 재부팅시키는 셈 | 재접속 지연으로 일부 전구가 안 켜지거나 늦게 켜지는 "부분 암전" 가능(추정). 아카라의 권장 구조는 "H2를 무선(디커플) 모드로 두고 전구는 상시 전원" | 아래 2장 "전구 결정" 참고. 5700K·100% 고정이면 **일반 전구 + H2 릴레이**가 더 단순·저렴·안정. 색온도 조절을 포기하지 않으려면 **T2 + H2 무선 모드 + 전구 상시전원** |

## 3. 소등 B1~B5 "매일 수동 입력"의 사고 시나리오와 대안

**사고 시나리오**

| # | 시나리오 | 결과 |
|---|---|---|
| S1 | 어제 입력한 시각이 "매일 반복"으로 남아 오늘 촬영 중 발동 | **촬영 중 암전** |
| S2 | 연장 결제 후 B 시각을 늦추는 걸 빠뜨림([연장] 씬은 A3만 재시작, B는 안 바뀜) | **연장 시간에 암전** |
| S3 | 저녁에 입력을 깜빡함 | 소등 안 됨(안전망은 자정 A4) — 암전은 아니지만 B의 존재 이유가 사라짐 |
| S4 | 5개 칸 중 어느 칸이 어느 예약인지 헷갈려 잘못된 칸을 끔 | S1 또는 S3 |
| S5 | "몇 시간 뒤" 방식일 때 허브 재부팅·정전 → 대기 중 타이머 소실 | 소등 안 됨 |

**절대 시각 vs "몇 시간 뒤"**: **절대 시각이 안전**. 허브 재시작에도 남고, 앱에서 "오늘 몇 시에 꺼진다"가 눈에 보여 검증이 쉬움. "몇 시간 뒤"는 시작 신호(입장 펄스)에 의존해 조기 도착·재입장마다 기준이 흔들림.

**프로그램 없이 줄이는 방법 (추천 순)**

| 방법 | 내용 | 효과 |
|---|---|---|
| **① 예약 슬롯 고정** | 네이버 예약 상품을 **시작 시각 고정 슬롯**(예: 09:30 / 13:30 / 17:30)으로만 판매. 소등 시각 = **다음 슬롯 시작 15분 전**(마지막 팀은 20:15) 으로 **영구 고정**. 연장(최대 다음 팀 전까지)도 그 안에 들어가므로 **연장 때 조작 불필요** | B1~B5 매일 입력 **0회**. 팀 사이 조명이 30~60분 더 켜져 있는 전기요금만 비용 |
| **② 재실 센서 기반 소등** | 메인홀 FP300 2~3개 → "부재 20분 지속 → 소등", "09:00~20:30 재실 → 점등" | B·A3·[연장] 씬 전부 삭제. 암전 시 자동 복구. 1장 참고 |
| ③ 1회성 타이머 | 아카라 시간 트리거에 "1회만/특정 날짜" 옵션이 있으면 S1 제거 | 입력 노동은 그대로 |
| ④ 지금 방식 유지 시 최소 규칙 | 칸 이름을 "B1 베이직 오전", "B2 패밀리" 식으로 역할 고정 · 입력 후 **켜진 칸 스크린샷 1장**을 매일 같은 카톡방에 남김 · 다음 날 아침 손님 입장 푸시가 오면 그 스크린샷 재확인 | S1·S4를 "두 번 보는" 수준으로만 완화 |

①은 설비 추가 없이 가능하고 ②와 합치면 가장 단단함. ①만 해도 **매일 밤 작업이 "비번 발송"만 남음**.

## 4. A1 펄스 + A3 4시간 30분 + [연장] 씬 구조의 허점 (촬영 중 꺼지는 경우 전부)

| # | 꺼지는 경우 | 원인 | 대책 |
|---|---|---|---|
| F1 | 조기 도착 15분 + 패밀리 4시간 + 연장 30분 | A3는 **입장 시각** 기준 4시간 30분 → 08:45 입장이면 13:15 소등, 손님은 13:30까지 | A3를 5시간으로, 또는 3장 ①/②로 A3 자체 제거 |
| F2 | 연장했는데 B 시각을 안 늦춤 | [연장] 씬은 A3만 재시작 | 3장 ① |
| F3 | 어제 B 시각 잔존 | 3장 S1 | 3장 ① |
| F4 | 재입장 펄스로 2초 암전 + 전구 재접속 수 초~수십 초(릴레이 방식일 때) | 손님이 차에 다녀와 비번 입력 → A1 → OFF→ON | 전구 상시전원(0장 3번) 또는 펄스를 "전구 그룹 OFF/ON"이 아니라 **허브에 아무 영향 없는 가상 장치(예: 플러그 1개) 토글**로 바꿔 조명은 건드리지 않기 |
| F5 | 퇴실 버튼 오작동(아이, 다른 가족 착각) | 1회 누름 | 2회 클릭/길게 누름 + 버튼 높이 1.5m 이상 |
| F6 | 대표의 [연장] 씬 탭 자체가 2초 암전 | 설계대로 | F4와 동일 |
| F7 | 08:45 이전 입장(앞당긴 예약·대표 입장)엔 A1 조건 밖 → 펄스 없음 → A3 시작 안 됨 | 조건 08:45~20:00 | A3를 쓸 거면 조건을 07:00~21:00으로 넉넉히 |
| F8 | 릴레이 OFF→ON 뒤 일부 전구가 "마지막 상태" 복구 실패 | 전구 전원복구 설정·재접속 | 설정을 "전원 복귀 = ON"으로(마지막 상태 아님) |
| F9 | 허브 재부팅 중 A3 카운트 재시작 또는 소실 | 아카라 "지속" 조건의 구현(확인 필요) | 10/16 시험 |
| F10 | 벽 스위치로 손님이 끄고 켬 → H2 상태 변화 → A3 카운트 재시작(이건 유리) / 혹은 H2 상태를 허브가 못 받아 A3가 꺼지지 않음 | — | 시험 |

구조적 결론: **입장 펄스로 타이머를 재시작하는 방식은 "사람이 있는지"를 "문이 열렸는지"로 추정하는 우회로**이고, 조기 도착·연장·재입장마다 예외가 생깁니다. 3장 ① 또는 ②로 바꾸면 F1~F3·F6·F7·F9가 한 번에 사라집니다.

## 5. K100 정기 비번 운영에서 문제가 되는 지점

| 상황 | 문제 | 대책 |
|---|---|---|
| **생성 자체** | 공식 FAQ: 정기 비번은 **블루투스 연결 후** 설정. 허브 경유 원격 생성이 되는지 미확인 🔴 | 10/16 집에서 시험. 안 되면 (a) **팀 사이 매장 방문 때 다음 날 비번을 미리 생성**(매일 매장에 오시므로 가능), (b) "손님" 사용자 1명을 만들고 **그 사용자의 비번만 교체**(원격 가능 여부 확인), (c) 고정 슬롯별 비번 3개를 월 단위로 돌리고 알림톡으로 그날 슬롯 비번만 발송 — 보안은 (a) > (b) > (c) |
| 복사 1회 | 화면 벗어나면 재열람 불가 | 생성 즉시 카톡 "나와의 채팅"에 붙여 두는 습관. 또는 비번을 직접 지정할 수 있으면 "예약자 전화 뒤 4자리 + 고정 2자리"처럼 **규칙형**으로(복사 불필요, 손님도 기억 쉬움) |
| **조기 도착** | 유효 시작 = 시작 15분 전. 아기 안고 20~30분 일찍 오는 가족이 복도에 갇힘 | 유효 시작을 **시작 45~60분 전**으로. 앞 팀 끝+15분 이후라면 겹칠 일 없음 |
| **연장** | 유효 종료 = 끝+15분. 연장 중 차·유모차 다녀오면 **재입장 불가** | 유효 종료를 **다음 팀 시작 15분 전**(마지막 팀은 20:30)으로 길게. 3장 ①과 같은 기준 |
| 재입장 | 유효기간 안이면 문제 없음 | — |

## 7. 에어컨

**오픈 시점엔 자동화하지 않는 것을 권합니다.** 이유: 시스템에어컨은 제조사(삼성이면 SmartThings) 영역이고 아카라와 묶으면 생태계가 하나 늘어남. 전원 차단 금지 원칙도 이미 세우셨음.

가장 단순한 방법 2단계:
1. **유선 리모컨 또는 제조사 앱의 주간 스케줄**로 "매일 09:00 ON(냉방 24℃ / 난방 22℃) · 20:30 OFF". 손님이 리모컨으로 바꿔도 다음 날 아침 복귀.

연동을 나중에 하려면: 삼성이면 SmartThings 루틴(시간 기반)이 아카라보다 쉬움. 아카라 M3의 IR로 제어하는 방법은 시스템에어컨(유선 리모컨)에는 보통 해당 없음(추정).

# 부록: 2차 심화 검토 (전제·업종·단일 실패점)

1차 검토는 "설계된 대로 잘 돌아가게 하려면"이었고, 2차는 **설계의 전제가 맞는지**를 봅니다.

## A. 전제 재검토: "조명이 세션 상태를 기억한다"는 구조

지금 설계는 **조명 ON = 이용 중**이라는 뜻을 조명에 심어 두고, 입장·퇴실·연장·종료를 전부 조명 조작(펄스, 타이머, 씬)으로 표현합니다. 그래서 문제가 생깁니다.

| 지금 조명이 맡은 역할 | 실제로 그 역할을 더 잘하는 것 |
|---|---|
| 세션 시작 신호(A1 펄스) | 도어락 비번 유효기간이 이미 세션을 정의함 |
| 세션 종료 강제(A3·B 소등) | **대표가 매 팀 사이에 직접 옴.** 초과 이용은 사람이 잡음. 마지막 팀은 비번 만료 + 자정 OFF |
| 에너지 절약(빈 방 소등) | 재실 센서 "부재 20분 → OFF" |
| 연장 반영([연장] 씬) | 비번 만료 시각을 넉넉히 잡으면 조명은 건드릴 필요 없음 |

**결론: 조명은 "사람이 있으면 켜고, 없으면 끈다"만 하면 됩니다.** 출입은 비번이, 종료는 대표 방문이 맡습니다. 이렇게 바꾸면 A1 펄스·A3·B1~B5·[연장] 씬이 전부 사라지고 남는 자동화는 4개입니다.

| 남는 자동화 | 내용 |
|---|---|
| 재실 ON | 영업시간(08:30~20:30) 중 메인홀 재실 감지 → 메인홀 ON |
| 부재 OFF | 메인홀 부재 20분 지속 → 메인홀 OFF |
| 자정 안전망 | 00:00 전체 OFF(항상 켜 두는 것 제외) — 유지 |
| 화장실 | FP300 재실/부재 — 유지 |

퇴실 버튼은 "즉시 소등" 편의 기능으로 남기거나 없애도 됩니다. 입장 푸시는 도어락 이벤트 알림으로 그대로 받습니다.

**이 구조의 약점과 대비**

| 약점 | 대비 |
|---|---|
| 재실 센서 오탐(선풍기·커튼·에어컨 바람) → 불이 안 꺼짐 | 에너지 손실만 발생. 자정 OFF가 막음. 간섭원 존 제외 설정 |
| 재실 센서 미탐(모두 가만히 있음) → 촬영 중 소등 | mmWave는 호흡·미세 움직임도 잡아 15명 공간에서 미탐은 드묾(추정). 꺼져도 **재감지 1~2초 내 자동 재점등**. 벽 스위치도 있음 |
| 센서 종류 선택 | **FP300(Zigbee)**: M3 자식 기기라 자동화가 허브 로컬. 단 2026-01 출시 신제품. **FP2(Wi-Fi)**: 성숙·30존이지만 Wi-Fi 기기라 조명 자동화가 클라우드를 탈 가능성(추정) → 인터넷 끊기면 재실 점등이 멈출 수 있음. 로컬 우선이면 FP300, 10/16 설치 전 재고 확인 |
| 165㎡ 커버 | FP300 약 6~7m·120°(추정) → 벽면 2~3개. 설치 후 구석(촬영 세트 안쪽)에서 가만히 앉아 5분 테스트 |

**타이머를 꼭 남기겠다면**: 조명을 껐다 켜는 펄스 대신 **아무것도 안 꽂은 스마트 플러그 1개를 "세션 깃발"**로 쓰세요. 입장 → 깃발 ON, 깃발 ON 지속 N시간 → 메인홀 OFF + 깃발 OFF, 퇴실 → 깃발 OFF. 조명은 한 번도 깜빡이지 않습니다.

## B. 도어락 운영을 "블루투스 제약이 사실"이라는 전제로 다시 설계

K100 정기 비번이 현장(BT)에서만 만들어진다면, **대표가 매일 매장에 온다는 사실이 해법**입니다.

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **① 방문 때 2~3일치 선생성** (추천) | 팀 사이 정리 방문 때 네이버 예약을 보고 **다음 2~3일 예약분 정기 비번**을 한 번에 생성·동기화 확인 → 그 자리에서 알림톡 발송까지 | 매일 저녁 집 작업 소멸. 예약 없는 날이 끼어도 2~3일 선행이면 구멍 없음 | 당일 예약(오늘 밤 예약 → 내일 아침)은 커버 못 함 → ②로 보완 |
| ② 요일별 비번 7개 | "월요일 08:30~20:30" 식 정기 비번 7개를 한 번만 만들고, 손님에게 그 요일 비번 발송 | 생성 작업 0회. 당일 예약도 커버 | 지난주 월요일 손님이 이번 월요일에 들어올 수 있음 → 월 1회(정리 방문 때) 7개 교체로 완화 |
| ③ 일회용 비번(원격·오프라인 가능) | 손님 "도착" 카톡 → 대표가 생성 → 15분 내 1회 | 완전 원격. 매장 인터넷 무관 | 대표가 실시간 응답해야 함. 외출 재입장마다 재발급. 보조 수단으로만 |
| ④ 도어벨 G4 통화 + ③ | 비번 모르는 손님이 벨 → 대표가 영상 통화로 확인 → 일회용 비번을 **말로** 알려줌 | 알림톡 실패·전화번호 오류까지 커버 | 대표 응답 필요 |

운영 권고: **①을 기본, ②를 당일 예약용, ③④를 백업**. 그리고 비번 생성 직후 **앱에서 "동기화 완료" 확인 + 손님에게 보낸 알림톡 내용에 "입장 가능 시간 ○○:○○~"를 반드시 포함**(조기 도착 민원 예방).

도어 하드웨어 쪽 추가 점검:
- **도어 클로저와 유모차**: 자동잠금은 문이 완전히 닫혀야 동작. 유모차·짐으로 문을 받쳐 두면 잠기지 않고 "문 열림" 경보가 반복됨. 클로저 힘 조절 + 안내문 "유모차를 먼저 들이고 문을 닫아 주세요".
- **방화문**: 4층 현관이 방화문이면 클로저 제거·고정 금지(소방법). 도어락 설치가 방화문 성능을 해치지 않는지 업체 확인.
- **내부 이중잠금(강제잠금) 기능 OFF**: 손님이 모르고 켜면 대표가 밖에서 못 들어옴.
- 건물 청소·관리인 출입 필요 여부 → 별도 지문/비번.

## C. 조명·전기: 사진 스튜디오라서 더 중요한 것

| 항목 | 내용 | 조치 |
|---|---|---|
| **LED 드라이버 돌입전류 vs H2 릴레이 정격** | 면조명 17개(680W)의 드라이버는 켜는 순간 큰 돌입전류를 냄. 스마트 스위치의 "저항부하 ○A" 정격은 LED 드라이버 부하엔 그대로 적용되지 않음(보통 훨씬 낮음). 한 채널에 17개면 릴레이 접점 수명 단축·안 켜짐 가능(추정) | 업체에 H2의 **LED/드라이버 부하 정격**을 물어 채널 분산 또는 H2가 전자접촉기(마그네트)를 구동하는 구조로 |
| **중성선 없음 + 스마트 전구** | 중성선 없는 스위치는 꺼진 상태에서도 전구 쪽으로 미세 전류를 흘려 자기 전원을 얻음 → 스마트 전구가 깜빡이거나 리셋됨. 아카라도 이 때문에 콘덴서를 따로 팜 | 전구 회선은 **중성선 확보 또는 상시전원(디커플)**. 릴레이로 전구를 끄는 구조를 피할 또 하나의 이유 |
| **플리커(깜빡임)** | 사진·영상 스튜디오의 핵심. 저가 40W 패널 드라이버는 카메라 셔터에서 줄무늬(밴딩)를 만듦 | 패널은 **플리커프리 드라이버** 명시 제품으로. 설치 후 폰 카메라 1/1000s로 촬영해 줄무늬 확인 |
| **연색성(CRI)** | 아기 피부톤. T2 전구는 CRI>90. 패널도 CRI 90 이상 | 견적서에 CRI 명기 |
| **색온도 혼합** | 패널 5700K와 전구 5700K가 실제로는 틴트가 달라 사진 화이트밸런스가 섞임 | 같은 제조사·같은 로트 또는 테스트 촬영으로 확인. 전구를 일반 전구로 바꾼다면 패널과 같은 5700K·CRI90 제품 |
| **전원복구 동작** | 정전 복구 후 전구가 "마지막 상태"면 꺼진 채 복구될 수 있음 | 전구·H2 모두 "전원 복귀 = ON" |
| **혼합 모드 제안** | "벽 버튼은 허브 없이도 동작"과 "전구 상시전원"을 동시에 만족하는 방법 | **면조명 채널 = 릴레이 모드**(허브 죽어도 벽 버튼으로 켜짐), **전구 채널 = 디커플 + 상시전원**(허브 경유). 허브가 죽어도 면조명으로 촬영은 가능 |
| **화장실 조명** | FP300이 켜고 끄는 조명에 **물리 스위치가 있는지** | 허브가 죽으면 화장실이 암실이 됨. 반드시 H2 채널(벽 버튼)로도 켤 수 있게 |
| 플러그 부하 | 인화기(포토프린터)를 자정 OFF 플러그에 꽂으면 매일 전원 차단 → 헤드 보호·캘리브레이션에 불리(추정) | 인화기는 상시전원 콘센트에 |

## D. 네트워크: 카메라 3대가 Zigbee를 밀어낸다

- **E1 3대 + G4는 전부 2.4GHz 전용**이고 상시 송신. 여기에 손님 15명 폰이 손님용 Wi-Fi 2.4GHz에 붙으면 2.4GHz가 포화 → **Zigbee(같은 대역)가 끊김**.
- 조치: **손님용 Wi-Fi는 5GHz만 켜기**(2.4GHz 손님 SSID 끄기), 카메라 비트레이트는 "표준/절약" 모드, M3는 유선, 공유기 2.4GHz 채널 고정 후 M3가 잡은 Zigbee 채널과 겹치지 않는지 확인.
- 2003년 건물 콘크리트 벽에서 공유기 1대로 165㎡+작업실+화장실의 카메라까지 커버가 되는지 설치 당일 신호 세기 확인. 안 되면 메시가 아니라 **유선 AP 1대 추가**가 정답(메시는 2.4GHz 백홀로 더 혼잡).

## E. CCTV와 아기: 카메라의 역할을 다시 정하기

영유아 스튜디오에서는 **아기 옷을 갈아입히고 기저귀를 바꾸는 장면이 메인홀에서 일어납니다.** 그 장면을 CCTV로 30일 보관하는 것은 법 위반 여부를 떠나 부모 신뢰와 영상 유출 시 피해가 치명적입니다.

| 지금 | 제안 |
|---|---|
| 입구 1 + 메인홀 2 (전경) | **입구 안쪽 1(출입·반입 동선) + 소품·장비 보관 구역 1**. 촬영 세트와 탈의·기저귀 교체 구역은 **화각 밖**으로 |
| 목적: 안전·파손 확인 | 파손 확인은 대표가 팀 사이에 직접 함. 카메라는 "누가 들어왔나·장비가 사라졌나"만 |
| 30일 보관 | 용량상 2K 3대 상시는 512GB로 16~20일(추정, 2~3Mbps 기준). **이벤트 녹화 + 14일**로 방침을 현실에 맞게 |
| 팬틸트 E1 | 회전 가능한 카메라는 "다른 곳을 비추지 않을 것"(25조 5항)의 입증이 어려움 → **회전 잠금** 또는 고정형 모델 |
| 안내판 | **"촬영 세트·수유실·화장실은 촬영하지 않습니다"를 안내판에 명시** → 신뢰 자산 |

## H. "불을 끈다"보다 부드러운 종료 신호

|---|---|

| 끝+15분 | 아무것도 안 함. 부재 20분 후 재실 센서가 끔 |
