## 2. 질문에 대한 답

### 1:1 채팅은 어떻게 켜나

1. PC에서 카카오톡 채널 관리자센터(center-pf.kakao.com)에 들어가 쁘띠레코드 채널을 연다. 채팅 메뉴는 **관리자 추가인증**(카카오톡 또는 문자)을 한 번 요구한다.
2. **채팅 설정**(메뉴 이름은 화면에 따라 "채팅 > 채팅 설정" 또는 "관리 > 상세설정 > 1:1 채팅")에서 **채팅 기능 ON**. 꺼져 있으면 손님 쪽 톡방에 입력창 자체가 안 보인다.
3. **채팅 가능 시간**을 요일별로 09:00~22:00으로 넣고, **채팅 불가 시간 안내 메시지**에 "상담 시간은 매일 09~22시입니다. 급한 출입 문제는 (스마트콜 0507 번호)로 전화 주세요"를 넣는다.
4. 프로필 설정에서 **채널 공개 ON**인지 확인한다.
5. 솔라피 알림톡 **발신프로필을 이 채널로** 연동한다. 그래야 알림톡과 손님 답장이 같은 톡방에 쌓인다.
6. 답장은 관리자센터 "채팅" 목록과 **카카오톡 채널 관리자 앱**(알림 켜기)에서 본다.

🟡 테스트 예약 때 알림톡을 받은 뒤 그 방에서 답장해 보고, 관리자 앱 채팅 목록에 들어오는지 1회 확인.

### 솔라피는 손님 번호만 알면 알림톡을 보낼 수 있나

된다. 알림톡은 손님이 채널을 추가하지 않아도 **휴대폰 번호만으로** 발송되는 정보성 메시지다. 조건은 가게 쪽에 있다.

- 카카오 **비즈니스 채널 인증**(사업자등록증, 1~3일)
- 솔라피에 **발신프로필(채널) 연동**
- 보낼 문장마다 **템플릿 심사 승인**(아래 5절 초안, 반려되면 수정 후 재심사)

실패하는 경우는 그 번호에 카카오톡 계정이 없거나, 손님이 알림톡 수신을 꺼 뒀거나, 채널을 차단한 경우 정도다. 실패는 솔라피 발송 결과에 바로 표시되므로 21시 루틴에서 보인다.

### 0507 안심번호로 대체 문자를 보낼 수 있나

**안 된다.** 솔라피 발신번호 FAQ는 "2022년 3월 2일부터 050, 030 등과 같은 안심번호는 사용이 불가"하다고 하고, 발신번호 가이드도 안심번호를 "발신주체 확인 불가한 번호"로 등록 불가 목록에 넣고 있다. 네이버 스마트콜 0507도 050 계열이라 같다.

- 대체발송에 쓸 수 있는 번호는 본인 명의 일반 번호뿐이다. 대표 010 번호(노출됨)이거나 추가 회선(eSIM·유심)이어야 한다.
- 그래서 고르신 대로 **대체발송을 끄는 것**이 맞다. 나중에 실패 건이 성가시면 추가 회선을 붙여 켜면 된다.
- 0507은 문자 수신도 지원하지 않는 것으로 알려져 있어 손님 답장도 못 받는다(공식 안내는 찾지 못함 🟡).

## 3. 본문에서 고칠 곳

### 3-1. 두 자리가 서로 어긋난 것

**보증금 반환 시점** (⑤ 8번 "다음 날" / ⑥ "다음 팀 입장 30분 뒤")
→ 1절 결정대로 "다음 날 21시 일괄"로 통일. 마지막 팀도 기준이 생긴다.

**취소 규정의 경계** (⑨ "24시간 이내 연락 있음"과 "노쇼인데 당일 연락"이 같은 상황을 가리킴)
→ 연락 시점을 시작 시각 기준으로 나눈다.

| 시점 | 이용료 | 보증금 |
|---|---|---|
| 3일 전까지 | 100% | 전액 이체 반환 |
| 3일 전 ~ 24시간 전 | 50% | 〃 |
| 24시간 이내, **시작 시각 전** 연락 | 30% 환불 **또는** 10일 안 1회 날짜 변경(손님 선택) | 〃 |
| **시작 시각 후** 당일 연락 | 환불 없음, 10일 안 1회 날짜 변경 | 〃 |
| 연락 없음(노쇼) | 환불·변경 없음 | 〃 |
| 매장 사정 | 100% | 〃 |

### 3-2. 빠진 것

**예약 마감 시각** (③ 영업 항목)
→ "예약 마감: 이용 전날 21시" 추가. 네이버 예약 설정에서 가장 가까운 형태로 넣고 🟡 테스트 예약 때 확인. 보증금 항목은 "전날 20시까지(20시 이후 예약은 즉시)"로.

**연장하면 비번이 먼저 끊김** (⑤ 6번, ⑦ 유효 시간)
정기 비번은 "끝 15분 후"까지라 30분 연장 중 잠깐 나갔다 오면 못 들어온다.
→ 연장 처리를 4단계로: ① 뒤 예약 비었는지 확인 ② 매장 안 QR 결제 확인(30분 25,000) ③ 아카라 소등 칸 지연 시간 늘리기 ④ 중간에 나갔다 올 일이 있으면 일회용 비번 발급.

**알림톡을 못 받은 손님 쪽 안내** (④ 연락 창구)
대체발송을 껐으므로 손님에게도 미리 알려 둔다.
→ 네이버 확정 알림 문구에 "출입 안내는 이용 전날 21시 카카오톡(쁘띠레코드 채널)으로 갑니다. 못 받으시면 채널 또는 (스마트콜 0507 번호)로 연락 주세요" 추가.

**CCTV 안내판** (⑧ 녹화, 3절 체크 5번)
이용 안내판과 별개로 **설치 목적·장소, 촬영 범위·시간, 관리책임자 연락처**를 적은 안내판이 법정 사항(개인정보보호법 제25조). "녹음 끄기 ✅"도 같은 조항의 녹음 금지와 맞는다.
→ 체크리스트에 "CCTV 안내판(법정 기재 사항)" 추가.

**도어락 자체가 죽었을 때** (⑩ 이상 상황)
"비번이 안 먹음"만 있고, 배터리 방전·고장이면 일회용 비번도 소용없다.
→ 행 추가: "도어락 반응 없음 → 비상 급전 단자에 보조배터리(기종 설명서 확인) → 그래도 안 되면 키박스 안 열쇠(위치·번호는 상황 때만 알려줌)". 체크리스트에 키박스·보조배터리 비치 추가.

**계좌번호 노출** (③ 보증금)
정리본에 KB 계좌번호가 그대로 들어 있다. 본문 원칙("확정 알림에만")대로 매뉴얼·전달문에는 "KB 계좌(확정 알림 전용)"로만 적고 번호는 네이버 확정 알림 문구에만 둔다.

**추가 질문 개수** (③ 추가 질문)
반환 계좌를 톡방 답장으로 받기로 했으므로 ③은 "필수 1개 추가"가 아니다. 1절 권장대로 "선택"으로 두거나, 빼서 2개로 간다.

### 3-3. 확인이 남은 것 🟡

**리뷰 혜택** (② 혜택)
공정위 표시(첫 줄 문구)는 네이버 리뷰뿐 아니라 **블로그 글 첫머리에도** 같이 넣어야 한다. 네이버는 대가성 리뷰를 사전 통보 없이 노출 제한·숨김 처리할 수 있으므로, 플레이스 리뷰 이용정책 원문에서 "리뷰 이벤트" 허용 범위를 1회 확인.

**세무 질문 목록** (⑪)
1. 오픈 쿠폰 2만 원(판매자 부담) = 매출 에누리로 과세표준 차감이 맞는지(네이버 정산 기준).
2. 리뷰 혜택 3만 원 계좌 환급 = 매출 에누리인지, **판매장려금**(부가가치세법 제29조 제6항, 과세표준에서 공제 안 됨)·광고선전비인지. 지급 증빙은 무엇으로 남기는지.
3. 보증금 = 예수금, 파손 차감분 = 손해배상금(부가세 과세 대상 아님) 처리 확인.
4. 현금영수증 의무발행: 2026년부터 **사진 처리업(749403)**이 의무발행업종에 추가됐다. 우리 등록 업종코드가 **인물사진 촬영업(749400)**이면 적용이 다를 수 있으니 업종코드 기준으로 확인. 송금 QR 수입(연장·인화·액자) 10만 원 이상 무기명 발급 절차.
5. 쿠폰·리뷰 환급을 받은 손님의 현금영수증 발급 금액 기준.

**알림톡 템플릿 중 "보증금 입금 안내"**
결제·입금을 유도하는 템플릿은 추가 소명 자료를 요구받을 수 있다. 반려되면 "입금 확인 안내" 형태로 문장을 바꿔 재심사.

**통신판매업 신고·개인정보 처리방침**
네이버 예약 선결제를 받으므로 통신판매업 신고 대상인지, CCTV·계좌 수집에 맞춘 개인정보 처리방침 게시가 필요한지 세무사·행정사에게 같이 확인.

### 3-4. 검산해서 이상 없던 것

- "7명 이상이 4시간 쓰면 패밀리가 유리": 베이직 7명 4시간 = 130,000 + 3명 45,000 + 연장 4회 100,000 = 275,000 > 패밀리 270,000. 6명이면 260,000으로 베이직이 유리. 맞다.
- 실제 부담 "13만 → 11만 → 8만": 맞다.
- 소등 "시작 + 2시간 15분"과 비번 "끝 15분 후": 베이직 2시간 기준 같은 시각이라 맞다. 패밀리 4시간 15분도 같다.
- 영업 09~20시에 하루 3팀: 패밀리 1 + 베이직 2는 4+1+2+1+2 = 10시간으로 들어가고, 패밀리 2 + 베이직 1은 12시간이라 안 들어간다. 네이버 달력이 자동으로 막아 주는지 🟡 테스트 예약 때 확인.

## 4. 21시 루틴 (수정본)

전날 18시 루틴을 21시로 옮기고, 반환·리뷰까지 한 번에 묶었다.

| 순서 | 할 일 |
|---|---|
| 1 | 내일 예약 목록 확인(21시 마감 뒤라 더 안 들어옴) · 촬영 세팅 신청 확인 |
| 2 | 보증금 입금 확인(입금자명 = 예약자명) → 미입금은 "입금 안내" 알림톡 |
| 3 | 입금 확인된 팀: 비번 준비(정기 비번은 매장 방문 때 미리 생성 🟡 블루투스 시험 후 확정) → "출입 안내" 알림톡 |
| 4 | 솔라피 발송 결과 확인 → 실패 건은 네이버 톡톡 🟡 또는 전화로 수동 안내 |
| 5 | 아카라 소등 칸 켜기(시작 시각 입력, 2시간 15분 / 패밀리 4시간 15분) · 필요하면 에어컨 예약 |
| 6 | 오늘 퇴실한 팀: CCTV·현장 점검 결과 확인 → "퇴실·반환 계좌" 알림톡 |
| 7 | 어제 퇴실한 팀: 계좌가 있으면 보증금 이체(차감분이 있으면 차감 후 나머지) · 미회신은 1회 재요청 |
| 8 | 리뷰 확인(사진 3장 + 블로그 + 첫 줄 문구) → 3만 원 이체 → 사장님 답글 |
| 9 | 취소 들어온 예약: 비번 삭제(🟡 블루투스 필요할 수 있음) + 소등 칸 끄기 |

당일에는 두 가지만 남는다. 시작 2시간 전에 미입금 팀에 한 번 더 안내하고, 시작 시각까지 안 들어오면 일회용 비번으로 입장시키고 매장 안 QR로 받는다.

## 5. 알림톡 템플릿 초안 (심사 제출용 4종)

변수는 `#{ }`로 표시했다. 광고 문구(할인·이벤트)가 들어가면 정보성 템플릿으로 승인되지 않으므로 리뷰 혜택 안내는 넣지 않았다. 리뷰 요청은 네이버 자동 알림과 매장 안내판으로 한다.

**① 출입 안내** (전날 21시, 입금 확인된 팀)

```
#{예약자명}님, 내일 쁘띠레코드 예약 안내입니다.
· 일시: #{날짜} #{시작}~#{종료}
· 주소: #{주소} 4층 (승강기 이용)
· 출입 비밀번호: #{비밀번호}# (시작 15분 전부터 종료 15분 후까지)
· 나가실 때: 문 옆 퇴실 버튼 2번 → 자동 소등
보증금 5만 원 입금이 확인되었습니다.
문의는 이 채팅방에 답장해 주세요. 급할 때 #{스마트콜번호}
```

**② 입금 안내** (21시 루틴과 당일 2시간 전, 미입금 팀) 🟡 입금 유도 문구로 반려될 수 있음

```
#{예약자명}님, #{날짜} #{시작} 예약의 보증금 5만 원이 아직 확인되지 않았습니다.
입금 계좌는 예약 확정 알림에 적힌 KB 계좌이며, 입금자명은 예약자명으로 해 주세요.
확인되는 대로 출입 비밀번호를 보내 드립니다. 문의는 이 채팅방에 답장해 주세요.
```

**③ 일회용 비밀번호 안내** (당일 미입금 팀, 비번 오류 시에도 사용)

```
#{예약자명}님, 오늘 #{시작} 입장용 일회용 비밀번호입니다.
· 비밀번호: #{비밀번호}# (15분 안에 1회만 사용 가능)
· 보증금 5만 원은 매장 안 송금 QR로 입금해 주세요.
문의는 이 채팅방에 답장해 주세요.
```

**④ 퇴실·반환 계좌 안내** (이용일 21시 루틴)

```
#{예약자명}님, 오늘 쁘띠레코드를 이용해 주셔서 감사합니다.
보증금 5만 원은 내일 21시까지 이체해 드립니다.
이 채팅방에 답장으로 반환 계좌(은행·계좌번호·예금주)를 남겨 주세요.
예약 때 반환 계좌를 적어 주신 분은 답장이 필요 없습니다.
```

## 7. 2차 정리본(10/21 v2) 검토

1차 결정 5건은 모두 정확히 반영됐다. 검산(실부담 8만, 소등 2시간 15분과 비번 끝 15분 후, "24시간 전" 마감이 21시보다 항상 빠름)도 이상 없다.

### 7-1. 이번에 확정한 것

| 항목 | 결정 | 본문에서 바뀌는 곳 |
|---|---|---|
| 예약 오픈 조건 | **알림톡 ①~④ 전부 승인 후 오픈** (현행 유지). 새로 추가한 ⑤는 차감 건이 생기기 전까지만 승인되면 되므로 게이트에 넣지 않는다(권장) | ④ 🔴, 🗓️ 1번 |
| 파손 차감 안내 | **⑤ 점검 결과 안내 템플릿 추가** (5종). 손님이 답장하지 않은 톡방에는 가게가 먼저 쓸 수 없으므로, 차감은 템플릿으로 알리고 손님이 답장하면 그때 사진·설명을 주고받는다 | ⑤ 표, ⑧ "톡방으로 연락" |
| 정기 비번 생성 시점 | **1순위: 매장에 공폰을 두고 원격으로 생성** (아래 7-2 조건으로 시험). **안 되면**: 퇴실 후 정리 때 내일 팀 비번을 미리 만들고 21시엔 보내기만 | ⑥ 3번, ⑩ 정기 비번, 🗓️ 4번 |

### 7-2. 공폰으로 원격 생성이 되나

된다. 단, 아래 조건을 다 갖춰야 하고, 되는지는 한 번 시험해야 한다.

| 조건 | 내용 |
|---|---|
| 기종 | **안드로이드, 갤럭시가 가장 확실.** 아이폰은 원격으로 화면을 보기만 되고 조작이 안 된다. 갤럭시가 아닌 안드로이드는 원격 앱의 "제어 플러그인"이 그 제조사를 지원하는지 먼저 확인 |
| 위치·전원 | 문에서 블루투스가 닿는 거리(수 m) 안, 손님 손이 안 닿는 곳(높은 선반·캐비닛) · 상시 전원 · 매장 Wi-Fi |
| 아카라 앱 | 대표 계정으로 로그인(또는 가족 구성원 공유) · 블루투스·위치 권한 "항상 허용" · 배터리 최적화 제외 |
| 원격 앱 | AnyDesk 또는 TeamViewer Host 설치 → **무인 접속 비밀번호** 설정 → 대표 폰·PC에서 접속. 갤럭시는 제어 플러그인이 자동 설치됨 |
| 배터리 | 24시간 충전은 배터리가 부푼다. 갤럭시 "배터리 보호(85%)"를 켜거나, 스마트플러그로 하루 2번만 충전 |
| 보안 | 공폰에는 다른 계정·결제수단을 넣지 않음 · 원격 앱 2단계 인증 · 화면 잠금 · 원격 앱 접속 알림 켜기 |

**시험 순서**: 작업실이나 집에서 공폰에 접속 → 아카라 앱 → 정기 비번 생성 → 문에서 실제로 열리는지 → 같은 방법으로 **삭제**까지 확인. 삭제가 되면 ⑥ 9번 "취소 건 비번 삭제 🟡"도 같이 해결된다. 둘 중 하나라도 안 되면 2순위(매장에서 미리 생성)로 간다.

### 7-3. 선택 없이 고칠 곳

- **④ 네이버 확정 알림 용도에 보증금 기한이 빠짐.** "5만 원 · 전날 20시까지(20시 이후 예약은 즉시)"를 계좌와 함께 넣는다. 손님이 기한을 보는 유일한 자리다.
- **⑥ 6번 "점검 확인 → ④ 퇴실 안내"를 분리.** ④는 21시에 그냥 보내고, 점검은 다음 날 21시(반환) 전까지만 끝내면 된다. 마지막 팀이 20시에 나가도 루틴이 안 밀린다.
- **⑥ 7번에 두 번 미회신 규칙 추가.** "2회 미회신 → 보류, 손님이 연락하면 기한 없이 지급".
- **리뷰 환급 계좌 = 보증금 반환 계좌.** ②와 ③에 "한 번 받은 계좌를 같이 쓴다"를 적어 리뷰 때 다시 묻지 않는다.
- **① 연장에 "(뒤 예약이 빌 때만)" 복원.** ⑦에는 있는데 손님이 보는 ①에는 없어 연장을 보장받는 줄 알 수 있다.
- **🗓️ 남은 일에 "홈택스 현금영수증 가맹점 가입" 추가.** 매장 QR 송금분은 가게가 직접 발급해야 하고 가입이 돼 있어야 발급된다. 의무발행업종이면 개업 60일 안이 기한.
- **④ 알림톡 실패 건 "전화"는 개인 번호가 뜬다.** 감수하기로 한 것이지만, 🗓️ 3번 테스트에서 톡톡 선발송이 되면 전화보다 톡톡을 앞에 둔다.

### 7-4. 알림톡 템플릿 ⑤ 초안

**⑤ 점검 결과 안내** (차감이 있는 팀만, 다음 날 21시 이체 전)

```
점검 사진과 자세한 설명은 이 채팅방에 답장하시면 보내 드립니다.
```

## 8. 3차 정리본(261022 완성본) 검토

1·2차 결정이 모두 반영됐고 15절 결정 이력도 이 문서와 일치한다. 현금영수증 가맹점은 9/22에 이미 가입돼 있으므로 7-5절에서 추가하라고 한 "가맹점 가입" 항목은 뺀다.

### 8-1. 이번에 확정한 것

| 항목 | 결정 | 본문에서 바뀌는 곳 |
|---|---|---|
| 예약 때 시간 늘리기 | 네이버 달력에서 **손님이 이용 시간을 직접 늘릴 수 있음**(기본 2시간, 클릭으로 3·4시간). 상품은 베이직·패밀리 2개로 충분. 검토자의 "옵션으로 받으면 달력이 겹친다"는 지적은 **철회** | 3-1에 "이용 시간: 기본 2시간, 30분 단위로 최대 4시간까지 손님이 선택" 행 추가 · 10-1 소등표 중간 행 유지 |
| 입금 후 취소한 손님의 반환 계좌 | **취소 건만 대표가 개인 문자로** 계좌를 묻는다(번호 노출 감수, 드묾). "취소 확인" 템플릿은 폐기 유지 | 6절 9번, 11절 "취소되면" |
| 확정 알림에 문구를 못 넣을 때 | 선호 없음 → **추천안 적용**: **⓪ 예약 접수 템플릿**을 5종과 함께 미리 심사 올려 두고, 확정 알림이 되면 안 쓴다. 쓰게 되면 21시 루틴 1번에 "오늘 들어온 예약에 ⓪ 발송"을 넣고 보증금 기한은 "안내 받은 다음 날 20시" | 3-5 🟡, 5절(6종), 6절 1번 |
| 공폰 원격 앱 | 선호 없음 → **추천안 적용**: 시험은 무료판으로 하고, 되면 **AnyDesk 개인사업자 요금제**로 전환(무료판은 상업 사용 감지로 끊길 수 있음). 요금은 🟡 확인 | 7-1 보안 행, 16절 4번 |

### 8-2. 네이버 이용 시간 선택이 가능할 때 같이 적을 것

- 3-1: 베이직은 최대 4시간까지 선택 가능, 패밀리는 4시간 고정(늘리기 없음).
- 🟡 테스트 3번에 추가: 3시간을 고르면 **추가 30분당 25,000이 자동 계산**되는지, 달력이 고른 시간만큼 막히는지.
- 1절 "넉넉히 쓰려면 예약 때 시간 늘리기" 문구는 유지. "뒤 예약이 빌 때만"은 **현장 연장**에만 해당한다고 구분.
- 6절 5번 소등 칸은 **예약된 시간**(2·2.5·3·3.5·4시간)에 맞춰 10-1 표대로 입력.

### 8-3. 선택 없이 고칠 곳

- **0절 🔴 오픈 조건과 5-② 메모가 어긋남.** 0절은 "①~④ 승인", 5-②는 "끝내 반려되면 확정 알림만으로 운영". 0절에 "②가 끝내 반려되면 ①③④ 승인으로 오픈"을 적어야 게이트가 무한정 안 밀린다.
- **③ 일회용 비번의 `#{추가안내}`는 자유 문장 변수라 반려 위험.** 고정 문장으로: "보증금을 아직 입금하지 않으셨다면 매장 안 송금 QR로 입금해 주세요. 재입장용이면 그대로 사용하시면 됩니다."
- **21시 이후 입금한 팀이 ①을 받는 경로가 없음.** 12절 "매일 아침"에 "어젯밤 미입금 팀 입금 확인 → ① 발송" 추가.

## 9. 리뉴얼본(261022 v2 · 무결제 예약 + 계좌이체) 검토

운영 구조가 바뀌어 1~8절의 네이버 결제·쿠폰·전날 20시 보증금 기준은 더 이상 쓰지 않는다. 아카라 설정, 취소표, 안내판, 세무 질문 대부분은 그대로 유효하다.

### 9-4. 오류·불일치

1. **입금 기한과 취소 시점이 다르다.** 손님에게는 "⓪ + 3시간"이라고 하면서 미입금 취소는 21시 루틴에서 한다. 10시에 신청한 손님의 자리는 13시가 아니라 21시까지 잡혀 있고, 13시~21시 사이에 입금한 손님은 "기한이 지났는데 입금됐다"가 된다. 기한을 루틴에 맞추거나(당일 21시), 3시간이 지나면 대표가 그때 취소해야 한다. → 결정 사항
2. **기한 뒤 입금의 처리 규칙이 없다.** "자리가 남아 있으면 확정, 아니면 전액 환불"을 적어야 한다.
3. **입금자명 불일치 규칙이 없다.** ⓪와 네이버 신청 알림 문구에 "입금자명이 다르면 답장으로 알려 주세요"를 넣는다.
4. **취소 환불에 계좌가 필요한데 받는 길이 없다.** 이용료를 계좌로 받았으므로 모든 취소 환불이 수동 이체인데, 입금 내역에는 이름만 찍힌다. 추가 질문 ③(선택)을 안 적은 손님이 네이버에서 취소하면 8절에서 정한 "개인 문자"가 보증금뿐 아니라 **이용료 환불 전부**에 적용된다. 빈도가 훨씬 높아졌으므로 ③을 필수로 돌리는 것이 맞다. → 결정 사항
5. **현금영수증 취소 절차가 없다.** 이용료 입금마다 발급하면, 취소 환불 때 홈택스에서 **취소 발급(수정)**을 해야 한다. 21시 루틴 "취소 환불" 옆에 붙인다. 발급에는 손님 휴대폰 번호가 필요하므로 네이버 예약자 정보의 번호를 쓴다.
6. **무결제 예약은 손님이 네이버에서 자유롭게 취소한다.** 취소 수수료가 자동으로 걸리지 않으므로 "네이버에서 취소했는데 왜 50%만 돌려주느냐"는 분쟁이 생긴다. 유의사항·⓪·확정 알림 3곳에 "취소 환불은 연락 시점 기준으로 계좌로 돌려드립니다"를 넣는다.
7. **리뷰 1만 원은 네이버 예약 손님만 받을 수 있다.** 다른 경로 손님은 예약자 리뷰를 못 쓸 가능성이 크고 영수증 리뷰도 안 된다. 리뷰 안내에 "네이버 예약으로 오신 분"을 붙이거나, 다른 경로 손님도 네이버 링크로 예약하게 한다. → 결정 사항
8. **① 확정 알림톡에 "이용 규칙에 동의한 것으로 봅니다"가 빠졌는지 확인.** 3차본 ①에 있던 문장이다. 이용료를 선입금 받는 구조에서는 규칙 고지 증거가 더 중요하다.
9. **비밀번호를 확정 즉시 보내는 구조의 전제가 흔들린다.** 즉시 보내려면 확정 때마다 주기 비밀번호를 원격으로 만들어야 하는데, 본문은 "블루투스에서만"이라고 쓰고 공폰 하나에 의존한다. 공폰이 죽으면 확정 알림도 못 보낸다. K100 스펙의 "원격 설정 주기 비밀번호"를 허브 연결 상태에서 재시험하고, 안 되면 비밀번호는 전날에 보내는 쪽이 안전하다. → 결정 사항
10. **KB 1일 이체 한도.** 9-3 표의 계산대로 취소 환불이 수동이 되면서 하루 100만 원을 넘길 수 있다. 한도 상향(OTP·보안매체)을 미리 해 둔다.
11. **4절 금액표에 이용 시간 늘린 경우가 없다.** 베이직 3시간이면 180,000 + 50,000 = 230,000. ⓪ 변수로 합계를 넣으므로 표에 "30분당 +25,000"을 적고 계산 실수를 막는다.

### 9-6. 이 구조의 약점

- **낮 시간 응답 의존.** ⓪·①이 대표 손을 거치므로, 대표가 몇 시간 못 보면 손님은 기한 안에 입금을 못 하거나 확정을 못 받는다. A와 D가 되면 ⓪가 사라지고 ①만 남는다.
- **전액 선입금 계좌이체의 신뢰 장벽.** 네이버페이 보호 없이 18만·32만 원을 먼저 보내야 한다. 처음 보는 가게에 보내기를 망설이는 손님이 생기고, 이탈률은 네이버 결제보다 높다. 8절 🟡10(결제 링크 전환 기준)이 이 때문에 필요하다.
- **취소·환불이 전부 수동이고 계좌가 필요하다.** 9-4의 4·5·6번. 분쟁과 이체 횟수가 늘고 KB 한도에 걸릴 수 있다.
- **다중 경로 수동 등록.** 입력 실수·중복, 리뷰 불가, 알림 누락. B로 없앤다.
- **비밀번호 즉시 발송.** 몇 주 전에 받은 비밀번호를 당일 못 찾는 손님, 취소 뒤 삭제 누락, 75개 한도. 리마인드 문구와 주간 삭제로 막는다.
- **현금영수증 의무가 가게로 넘어옴.** 네이버 결제 때는 네이버가 발급했지만 이제 가게가 건별로 발급·취소한다. 의무발행업종이면 누락 가산세 20%.
- **통신판매 규제는 그대로.** 결제 수단을 바꿨어도 온라인으로 청약을 받고 선입금을 받으면 통신판매다. 면제 기준 확인(11-1)이 더 중요해졌다.
- **네이버 노출.** 네이버 결제·쿠폰을 끄면 플레이스 노출에서 불리하다는 통설이 있으나 확인된 사실은 아니다(확실도 낮).

### 9-8. 테스트 예약 때 같이 확인할 것 (리뉴얼 기준)

**일일 비상 비번 규칙**

- 하루 1개, 유효 09:00~20:15(영업시간 + 15분), 이름은 "비상MMDD".
- 원격 생성이 되면 필요한 날 그때 만들고, 안 되면 매장 방문 때 **7일치를 미리** 만든다(75개 한도 안).

**답변에 섞인 질문 세 가지**

1. **"예약 취소는 수동만 가능하겠지?"** → 네. 네이버의 자동 취소는 네이버페이 결제형의 "결제 대기 시간"에만 있고, 무결제 직접확정 신청은 대표가 취소해야 한다(확실도 중). 3시간을 지키려면 ⓪를 보낼 때 폰 타이머를 같이 켜는 습관이 필요하다.
2. **CTP의 "1개의 예약상품으로 묶어서 옵션 선택으로 진행하면 가능합니다"** → 네이버는 예약 상품 하나를 자원(방) 하나로 본다. 베이직·패밀리를 상품 2개로 만들면 자원이 2개라 같은 시간에 베이직 1팀 + 패밀리 1팀이 동시에 잡힌다. 상품을 "셀프 촬영" **1개**로 만들고 베이직/패밀리를 그 안의 **옵션**으로 두면 자원이 1개라, 결제 없이 신청만 들어와도 그 시간대가 다른 손님에게 막힌다는 뜻이다. 지난번 "같은 달력 연결 🟡"의 답이 이것이다. 주의할 점은 옵션으로 묶으면 화면 금액이 "기본가 + 옵션가 + 시간 추가"로 섞여 보일 수 있다는 것. 무결제라도 ⓪에서 합계를 다시 알려 주는 것은 유지하고, 패밀리 옵션 + 4시간을 골랐을 때 금액이 어떻게 보이는지 테스트 5번에서 확인한다.
3. **"3번 선택이 어떤 질문이지?"** → 3차본 3-2의 네이버 예약 **추가 질문 ③ "보증금 반환 계좌(은행·계좌번호·예금주)"**, 손님이 예약 신청 화면에서 적는 칸(선택)이다. 톡방에서 받기로 했으므로 이 칸은 선택으로 두거나 빼도 된다.

**2번 "퇴실 시간쯤 자동으로 가게 할 수 있나"에 대한 답**: 네이버 달력을 읽어 저절로 보내는 방법은 없다(네이버 예약 API 없음). 대신 솔라피 **예약 발송**에 날짜·시각을 넣어 두면 그 시각에 자동으로 나가므로, ①을 보내는 순간 ②를 같이 걸어 두면 "확정된 예약 = ② 예약됨"이 된다. 취소 건만 콘솔에서 예약 취소를 눌러 주면 된다. 연장이 생기면 종료 시각이 밀리므로, 종료 직후로 걸어 두면 연장 중에 ②가 갈 수 있다.

**5번 "통으로"의 구현 방식**: 종료 + 15분에 끄려면 아카라가 그 팀의 종료 시각을 알아야 하는데, 그것을 알려 주던 것이 소등 칸(시작 시각 입력)이었다. 입력 없이 하려면 아래 셋 중 하나다. 임시 비번은 사용자에 묶이지 않아 "특정 사용자 해제" 트리거로 베이직·패밀리를 가르는 방법은 쓰기 어렵다.

| 방식 | 동작 | 장점 | 단점 |
|---|---|---|---|
| A 재실 감지 | 입장 → 켜짐. 꺼짐 = 퇴실 버튼 **또는** 메인홀 부재 20분 **또는** 새벽 1시 | 입력 없음 · 실제로 나간 뒤 꺼짐 · 전기 절약 | 센서 1~2개(5~8만 원대) · 종료+15 "나가세요" 신호 없음 |
| B 고정 타이머 | 임시 비번 해제 → 켜짐 + **4시간 15분** 뒤 꺼짐. 꺼짐 = 퇴실 버튼 또는 타이머 또는 1시 | 입력 없음 · 비용 0 | 베이직 팀은 버튼을 안 누르면 최대 2시간 더 켜짐(뒤 팀 웰컴이 다시 켬) · 종료+15 신호 없음 · 🟡 아카라 지연 최대치가 4시간 15분 이상인지 |
| C 원안(소등 칸) | 전날 칸 켜고 시작 시각 입력 → 종료+15 정확히 꺼짐 | 종료+15 "나가세요" 신호 있음 | 매일 입력 · 깜빡하면 1시까지 켜짐 |

종료 + 15분 소등은 "나가세요" 신호 역할도 했으므로, A·B를 고르면 그 신호는 안내판·매장 시계·① 문구("종료 15분 후 비밀번호 만료")로 대신한다.

### 9-14. ② 퇴실 안내의 내용과 소등 결정

**② 퇴실 안내(이용일 발송, 결정 4 반영본)** — 3차본 ④를 리뉴얼에서 ②로 번호만 바꾼 것

```
[쁘띠레코드] 이용 감사 안내

#{고객명}님, 오늘 쁘띠레코드를 이용해 주셔서 감사합니다.

보증금 50,000원은 점검 후 내일 21시까지 이체해 드립니다.
이 채팅방에 답장으로 반환 계좌(은행·계좌번호·예금주)를 남겨 주세요.

불편하셨던 점이 있으면 편하게 말씀해 주세요.
```

하는 일 세 가지: ① 감사 인사와 반환 시점 고지 ② **계좌를 답장으로 받기**(답장이 오면 1:1 톡방이 열려 그 뒤 대화가 됨) ③ 불편 사항을 먼저 듣기(별점 방어). 리뷰 1만·블로그 2만 안내는 광고성이라 알림톡에 못 넣고, 손님이 답장한 뒤 톡방 채팅으로 보낸다.

**소등(결정 5 보충)**: 대표가 아카라 앱 자동화로 직접 구현. 9-13의 B(임시 비번 해제 → 켜짐 → 4시간 15분 뒤 꺼짐, 퇴실 버튼·새벽 1시 유지)로 기록. 확인할 것 하나: 아카라 지연 최대치가 4시간 15분 이상인지.

**결정 대기 7(② 발송 시각)에 보기 하나 추가**: ①에 "이용 후 이 방에 답장으로 반환 계좌를 남겨 주세요"를 넣고 ②를 아예 생략하는 안. 템플릿이 하나 줄지만, 몇 주 전 ①을 받은 손님이 이용일에 그 문장을 기억해 답장할 확률이 낮아 보류 건이 늘어난다.

### 9-15. ② 발송 시각 결정과 시트 자동 발송

**결정 7**: ② 퇴실 안내는 연장과 관계없이 **예약 종료 시각에** 나간다. 솔라피 예약 발송 대신 **구글 시트에 적어 두면 시각에 맞춰 자동으로 나가는** 방식으로 한다. 같은 시트로 ① 확정·비번도 보내므로 솔라피 콘솔에서 변수를 입력할 일이 없어진다.

스크립트: `알림톡-자동발송.gs` (같은 폴더). 구글 시트의 Apps Script에 붙여 넣고 10분 트리거를 만들면 된다.

| 열 | 내용 | 누가 적나 |
|---|---|---|
| A~F | 예약자명 · 전화 · 이용일 · 시작 · 종료 · 상품 | 대표가 신청 알림을 보고 한 줄 |
| G | 비밀번호 | 대표가 주기 비번을 만든 뒤 |
| H | 상태: 신청 → **입금확인** → 확정 → 이용완료 / 취소 | 대표가 '입금확인'까지만, 그 뒤는 스크립트 |
| I·J | ①·② 발송 시각 | 스크립트 |
| K | 비고(오류) | 스크립트 |

대표가 하는 일은 두 번뿐이다. 신청이 오면 한 줄 적고, 입금이 확인되면 비밀번호를 적고 상태를 '입금확인'으로 바꾼다. 10분 안에 ①이 가고, 종료 시각이 지나면 ②가 간다. 취소면 상태를 '취소'로 바꾸면 끝이다(예약 메시지를 따로 취소할 필요 없음).

처음 켤 때 확인할 것 🟡
- 템플릿 변수명(`#{고객명}` 등)이 승인된 템플릿과 글자 하나까지 같은지. 다르면 솔라피가 거절한다.
- `testMode: true`로 대표 번호에만 보내 보고, ①·② 둘 다 제대로 오면 `false`로.
- 솔라피가 알림톡에도 `from`(발신번호)을 요구하면 오류가 K열에 남는다. 그때는 솔라피 문의(대체발송을 끈 알림톡은 발신번호 없이 가는 것으로 알고 있음).
- 시트 공유는 대표·남편만. API 키가 스크립트 안에 있으므로 시트를 외부에 공유하지 않는다.

### 9-16. 템플릿이란, 그리고 남은 결정·확인 목록 (10/23 기준)

**템플릿** = 알림톡으로 보낼 수 있도록 카카오가 미리 심사해 승인한 "정해진 문안". 알림톡은 아무 문장이나 보낼 수 없고 승인된 문안만 보낼 수 있다. 문안 안에서 손님마다 달라지는 자리(이름·날짜·비밀번호)는 `#{고객명}`처럼 변수로 비워 두고 보낼 때 채운다. 솔라피에 문안을 올리면 카카오 심사(1~3영업일, 반려되면 고쳐서 재심사) → 승인되면 템플릿 ID가 생기고 → 그 ID를 스크립트 CONFIG에 넣는다. 지금 쓸 템플릿은 4종: ① 확정·비번 ② 퇴실 안내 ③ 일회용 비번 ⑤ 점검 결과. 네이버 신청 알림에 계좌를 못 넣는 것으로 나오면 ⓪ 예약 접수가 하나 더 붙는다.
